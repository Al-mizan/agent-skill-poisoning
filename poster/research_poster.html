Background

Context: Tool-using LLM agents extend capabilities via modular skill packages (SKILL.md manifests, MCP configurations) that combine executable function schemas with free-form natural-language instructions.

Problem: Because agents ingest untrusted skill text directly into their reasoning loop, this creates Control-Data Conflation — a semantic supply-chain attack surface where documentation becomes executable guidance.

Gap: All existing active exploitation benchmarks operate exclusively in English, leaving cross-lingual manipulation unstudied. Static audits show scanners flag non-English packages up to 5× more frequently with near-zero precision, but whether such manifests actually hijack runtime tool execution remains unmeasured.

Motivation & Challenges
🔴 Challenge 1
Safety alignment concentrated on English; multilingual models comprehend non-English instructions but guardrails fail to intercept them.
🔴 Challenge 2
Static keyword/YARA scanners calibrated for English syntax achieve 0% precision on non-Latin skill manifests.
🟡 Gap 1
No active runtime benchmark measures cross-lingual skill poisoning across low-resource languages and code-mixed registers.
🟡 Gap 2
Language invariance of deterministic runtime policy enforcement remains unmeasured.
Key Concepts:
  • Linguistic Proficiency Paradox Models comprehend multilingual instructions; safety filters do not.
  • English Calibration Gap Alignment and guardrails perform significantly better on English prompts.
Research Questions
RQ1 (Runtime Exploitation): Do non-English/code-mixed skill manifests increase Attack Success Rate compared to English equivalents?
RQ2 (Scanner Bias): How do static scanners and prompt-level filters perform on cross-lingual skill manifests?
RQ3 (Model Stratification): How do proprietary vs. open-weights models compare in resisting cross-lingual manipulation?
RQ4 (Language Invariance): Can a deterministic policy enforcement module provide language-invariant protection without utility penalty?

Proposed Methodology

We construct a systematic evaluation benchmark across three linguistic registers and three defense tiers, measuring active runtime exploitation of poisoned skill manifests in tool-using LLM agents.

Linguistic Registers (Native-Speaker Authored)
🇬🇧 English (en) — Formal technical baseline 🇧🇩 Bangla (bn) — Native-script low-resource 🔀 Banglish (bn-en) — Code-mixed colloquial

Benchmark: Phase 1 pilot spans 5 domains (pdf, git, email, internal-comms, webapp-testing) → Phase 2 expands to 50 enterprise workflows across 4+ registers including Mandarin and Spanish. Each task pairs an authentic user prompt with clean tool expectations and 3 skill variants.

Defense Evaluation Framework (3 Tiers):
❌
Tier 1: Static Keyword & YARA Scanner
Represents current marketplace vetting. Scans manifest text for known inducement strings and description-length heuristics.
Result: 100% bypass on non-English manifests
⚠️
Tier 2: Prompt-Level Isolation
Injects explicit security warnings into system prompt directing the model to ignore side-effect instructions in skill documentation.
Result: Reduces ASR but degrades utility by up to 23.1%
✅
Tier 3: Deterministic Policy Enforcement (ADR-0002)
Positioned between reasoning loop and tool adapters. Evaluates declarative capability tokens, path invariants, and workspace boundaries at the execution seam.
Result: 0% ASR across all languages, 100% benign utility, sub-ms latency
Evaluation Metrics
SSR: SSR = (Σ 𝕀[Selected = Target]) / N × 100%
ASR: ASR = (Σ 𝕀[Canary Executed]) / N × 100%
BUR: BUR = (Σ 𝕀[Clean Task Completed]) / N × 100%
DRR: DRR = (ASRundefended − ASRdefended) / ASRundefended × 100%

SSR = Skill Selection Rate · ASR = Attack Success Rate · BUR = Benign Utility Retention · DRR = Defense Robustness Rate

Key Findings
🔴
Runtime Vulnerability Confirmed: Cross-lingual skill poisoning reliably compromises live agent tool dispatch across all 26 enterprise domains with 100% ASR when undefended.
🟡
Scanner Breakdown: Static scanners achieve 0% detection on non-English manifests while generating 23.1% false denials on English skills.
🟠
Prompt Isolation Trade-Off: Soft prompt warnings reduce ASR but degrade task completion by up to 23.1% — an unacceptable utility penalty.
🟢
Deterministic Protection: ADR-0002 runtime enforcement achieves sub-millisecond, language-invariant defense with 100% task completion and 0% false denials.
Conclusion & Future Work

Conclusion: We present the first active runtime evaluation of cross-lingual skill supply-chain poisoning. Our results demonstrate that English-calibrated static scanners and prompt-level filters fail against non-English manifests, while deterministic runtime policy enforcement provides language-invariant protection without utility degradation.

Future Work:
  • Scale benchmark to 50 enterprise workflows across Mandarin, Spanish, and additional low-resource languages.
  • Evaluate frontier proprietary models (GPT-4o, Claude) alongside open-weights architectures.
  • Conduct defense ablation studies measuring memory, token overhead, and multi-turn stability.
  • Submit manuscript to top-tier security/NLP conference.
